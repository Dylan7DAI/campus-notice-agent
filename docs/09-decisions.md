# 设计决策与变更规则

以下为初始默认决策，不是永久禁令。修改需写下原因、受影响契约/测试、迁移和回退；用户新约束优先。

| ID | 决策 | 理由 / 重新评估条件 |
| --- | --- | --- |
| ADR-001 | 单人local-first校园MVP，三类通知 | 先测试变化一致性；真实多人需求明确后加身份/授权 |
| ADR-002 | TS模块化单体+SQLite | 简化编码上下文和本机复现；高并发/跨用户上线再评估DB |
| ADR-003 | 规则状态机优先，模型只提议 | 可精确测试错误更新；需跨进程长任务时再看LangGraph/工作流框架 |
| ADR-004 | 首次/后续变更均人工确认 | 避免模糊通知造成误写；有充足离线证据与可撤销机制后再评估自动化 |
| ADR-005 | 审计日志+当前投影，非全量事件溯源 | 满足追溯而减少重放复杂度；不声称当前投影可仅靠审计完整重建 |
| ADR-006 | 完成记录绑定requirement_epoch | 新增材料不吞掉历史完成，当前有效性可明确验证 |
| ADR-007 | 截图识别可校正，文本fallback | OCR质量不应阻塞领域内核；未接真实provider就不宣称截图能力完成 |
| ADR-008 | 交接为本地用户记录 | 没有账号/消息系统，不能验证第三方真实接受 |
| ADR-009 | ICS文件导出 | 无需外部账户授权；不能保证日历更新，持续同步留待后续 |
| ADR-010 | 独立实现，借鉴Donetick机制 | 已有功能存在重叠且AGPLv3许可；复制复用另行评估义务 |

新增ADR格式：日期 / 状态 / 问题 / 考虑的方案 / 选择及原因 / 影响的文档、schema、E案例 / 迁移 / 回退 / 验证结果。实现偏离规格不能只在聊天中说明。
