# M7 用户试用与下一轮决策

M7 的验收需要真实操作者完成固定素材和顺序的试用。当前仓库没有用户试用记录，因此 M7 不能标记为通过；模型评估、离线场景和浏览器测试不能代替用户试用。

## 运行方式

先复制模板到受控的本地目录，并只填匿名 ID 和数值结果：

```powershell
Copy-Item evals/m7/pilot.template.json $env:TEMP/campus-m7-pilot.json
npm run eval:m7 -- --input=$env:TEMP/campus-m7-pilot.json --out=evals/runs/m7-pilot-local/summary.json
```

使用空模板时命令应以 exit 1 结束，并输出 `status: "not_run"`。输入不符合 schema 或包含未允许字段时以 exit 2 结束。只有完整试点数据、配对记录、三项观察问题、校正时间审查和下一轮决策都存在，且确定性门槛通过时才会输出 exit 0 / `status: "passed"`。

## 试点协议

- 招募 8–12 位操作者；只记录格式为 `pNN`/`pNNN` 或 `anon-...` 的匿名 `participant_id`，不得写姓名、学号、联系方式、电话号码或通知正文。报告器会拒绝不符合格式的参与者 ID；这只是输入格式闸门，不是对外部身份的认证。
- 每位操作者完成两个难度匹配的事项配对；每个配对分别执行 A 手动清单、B 一次性通知抽取、C 本系统。每个配对必须有一条 A、B、C 记录，顺序平衡，素材互换。
- 固定通知内容、完成标准和允许时间。记录要求总数、漏项数、错误更新数、提案错误数、校正秒数、是否严重误解、是否完成及失败类别。
- 不记录自由文本访谈或模型原文。观察到的设计问题用匿名 `issue_code` 和次数记录，至少三类。
- 试点完成后由负责人记录 `decision.outcome`：`continue`、`shrink_scope` 或 `pause`；另记录校正时间是否可接受。脚本只计算并列出结果，不替负责人替数据作普遍性结论。

## 报告解释

报告同时给出 A/B/C 各自的分母、漏项率、错误更新率、提案错误率、校正时间中位数、失败分类和严重误解数，并给出 C 相对 B 的配对差值。`passed` 是“本次 M7 数据包完整且预设试点门槛通过”，不是对所有学生或真实校园通知的普遍保证。

门槛包括：参与者 8–12 人；每人 6 个会话、两个完整 A/B/C 配对；至少三项观察到的设计问题；严重误解为 0；C 在漏项和错误更新上不劣于 B 且至少一项改善；校正时间审查为可接受；已记录下一轮决策。若缺少数据、配对、审查或决策，报告保持 `not_run`/`incomplete`，不会补造百分比。

## 已知限制

- 当前没有真实参与者、同意记录、退出记录或配对结果，故不能声称 M7 已执行或改善了用户结果。
- 该脚本不会验证操作者是否真实完成任务，也不会从原始日志推断真值；输入仍需由负责人按固定 rubric 脱敏后录入。
- 小规模试点不能支持普遍优越性推断；应优先查看配对差值、分布和失败案例。
- M7 报告不替代 M4 真实模型质量、M5 外部日历客户端兼容性或 M6 备份/恢复验收。
